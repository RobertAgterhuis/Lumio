## 1. Summary for This Team

Lumio's UX has a clear structural problem: the product's core safety-critical flow (Shamir heir unlock) has never been tested with real users, and the primary onboarding path (7-step wizard) imposes a cognitive load of 8/10 — at the ceiling of acceptable complexity for a general consumer population, particularly for the B2C target segment of 40–65 year olds facing emotionally charged life-planning tasks.

The product's architecture is thoughtfully designed for its privacy mandate — offline-first, local storage, no telemetry — but this imposes UX constraints that have not all been resolved. The 15-minute idle session timeout silently destroys wizard progress with no partial-save mechanism. The AVG consent text is written at C1 readability level (academic) for an audience that needs B1/B2 (pre-intermediate to good intermediate) — meaning users are consenting without full comprehension, which has both legal and trust implications.

The strongest UX signal is the existing i18n infrastructure: all strings are correctly internationalised via `next-intl`, no hardcoded production strings were detected, and both NL and EN message files exist. This foundation supports future language expansion at minimal marginal cost. Storybook 10 with the a11y addon is in place, covering 17/25 components — a good foundation to build on.

The most urgent action is to execute the Shamir UX test (protocol ready at `devdocs/shamir-ux-test-protocol.md`) before any sprint work on the heir flow proceeds. This test is already designed; it simply needs to be scheduled and run.
