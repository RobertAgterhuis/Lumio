# Accessibility Guidelines (A11Y)

> Accessibility standards and practices for the Lumio design system.

## Standards

Lumio targets **WCAG 2.1 Level AA** compliance.

## Color & Contrast

### Requirements
- **Normal text:** 4.5:1 minimum contrast ratio
- **Large text (≥18pt or ≥14pt bold):** 3:1 minimum contrast ratio
- **UI components and graphical objects:** 3:1 minimum contrast ratio

### Token Compliance
All semantic color tokens are designed as contrast-safe pairs:
- `text-primary` on `bg-background` ✅
- `text-danger` on `bg-danger-100` ✅
- `text-warning` on `bg-warning-100` ✅
- `text-info` on `bg-info-100` ✅
- `text-success` on `bg-success-100` ✅

Dark mode tokens are independently validated for contrast.

### Do Not
- Use `text-muted-foreground` on colored backgrounds without checking contrast
- Rely solely on color to convey information — always pair with icons/text

## Keyboard Navigation

### Requirements
- All interactive elements reachable via Tab
- Visible focus indicator on all focusable elements
- Escape closes dialogs and dropdowns
- Enter/Space activates buttons and checkboxes

### Component Support
| Component | Keyboard | Notes |
|-----------|----------|-------|
| Button | Tab, Enter/Space | Native |
| Checkbox | Tab, Space | Native `<input type="checkbox">` |
| Input/Textarea | Tab | Native |
| Select | Tab, Arrow keys | Native `<select>` |
| Dialog | Tab trap, Escape | Custom focus management |
| Tabs | Tab between list/content | Trigger within TabsList |
| NotificationsDropdown | Escape to close | Click-outside close |

### Focus Indicators
All interactive components use:
```css
focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2
```

## ARIA Roles

| Pattern | ARIA | Component |
|---------|------|-----------|
| Status messages | `role="alert"` | `<Alert>` |
| Progress bars | `role="progressbar"` + `aria-valuenow/min/max` | `<Progress>` |
| Dialogs | `role="dialog"` + `aria-modal="true"` | `<Dialog>` |
| Checkboxes | Native `<input type="checkbox">` + `<label>` | `<Checkbox>` |
| Tabs | `role="tablist"` / `role="tab"` / `role="tabpanel"` | `<Tabs>` |

## Motion & Animation

### Reduce Motion
Users who prefer reduced motion (`prefers-reduced-motion: reduce`) should see:
- No transition animations
- No loading spinners (use text "Laden..." instead)
- Instant state changes

**Status:** Partially implemented. Token architecture supports `--duration-*` tokens; a global `prefers-reduced-motion` override layer is planned.

## Screen Reader Testing

### Priority Pages
1. **Dashboard** — Announcements, completion percentages
2. **Settings** — Form controls, status messages
3. **Testament/Uitvaart** — Complex forms with conditional fields
4. **Eigenaar** — Profile data with edit dialogs

### Testing Checklist
- [ ] All alerts announced on appearance
- [ ] Form errors linked to fields via `aria-describedby`
- [ ] Dialog focus trapped and restored on close
- [ ] Progress bars announce current value
- [ ] Meaningful alt text on all informational icons

## Component Guidelines

### Buttons
- Use descriptive labels: "Opslaan" not "OK"
- Disabled buttons keep visible text (never `display: none`)
- Loading state: disable + show spinner + announce "Laden..."

### Forms
- Every input has a visible `<Label>`
- Error messages associated via `aria-describedby`
- Required fields marked with `aria-required="true"` or `required`

### Alerts
- Always use `<Alert>` component (has `role="alert"`)
- Never use raw `<div>` for status messages
- Include icon + text (not color alone)

### Dialogs
- Focus moves to dialog on open
- Focus returns to trigger on close
- Escape key closes dialog
- Background is inert while dialog is open

## Color Blindness Considerations

| Pattern | Issue | Mitigation |
|---------|-------|------------|
| Red/green financial amounts | Indistinguishable for protanopia/deuteranopia | Include +/- prefix or up/down arrow icons |
| Status badges | Color-only differentiation | Paired with text labels |
| Progress bars | Single-color fill | Include percentage text (`showValue`) |
